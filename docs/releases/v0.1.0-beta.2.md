# Mira v0.1.0-beta.2

发布准备日期：2026-11-16。此文档描述待发布版本，不表示安装包已上传或已完成平台验收。

这是 `0.1.0` 的第二个 Beta，在 `v0.1.0-beta.1` 基础上继续迭代，仍属于预发布版本。GitHub tag 使用 `v0.1.0-beta.2`，应用与 npm 元数据使用 `0.1.0-beta.2`。

## 相较 Beta 1 的主要变化

- **可选子应用**：支持从 GitHub Release 目录发现、安装、更新和卸载子应用，校验包大小、SHA-256、清单身份与兼容性；安装和更新后按提示重启生效。调试版可与正式子应用并存，本地目录删除会同步应用列表。
- **Mira SDK**：接通 API 1.4 / SDK 0.4.0，提供子应用独立 SQLite、文件区、目录授权、隔离视图、模型调用、联网搜索和通知。模型密钥由 Mira 持有，能力调用受身份与权限校验控制。
- **Workbench 支持**：增加原生网页承载、标签页缓存与分离窗口，以及在默认浏览器中打开新窗口的偏好。为 Workbench 在线安装小程序提供受限资源下载；小程序安装、授权与数据管理由 Workbench 负责。
- **资源管理**：完善资源与应用存储管理，支持查看和清理相关存储；改进资源窗口在 macOS、Windows 下的窗口控制与标题栏行为。
- **模型与交互**：新增 OrcaRouter 服务商，改进模型菜单、流式文字显示、引用预览、加载动画与 macOS 原生全屏体验。
- **文档与结构**：更新 Mira 使用指南，仓库迁入 MiraWorkspace；移除旧内置小说模块，后续小说创作能力按可选子应用接入。

Mira 与 Harness 指同一个主应用；Workbench 是独立发布的可选子应用，其 `v0.1.1` 不等于 Mira 的版本。SDK 的 `v0.4.0` 也独立维护。

## 从 Beta 1 升级

1. 退出 Mira，备份用户目录下的 `~/.mira` 和重要项目文件。
2. 使用与操作系统及架构匹配的 Beta 2 安装包替换旧程序，不删除用户数据目录。
3. 启动后在“设置 → 关于”确认版本为 `v0.1.0-beta.2`，检查会话、模型配置和项目入口。
4. 在“设置 → 应用扩展”检查子应用；按兼容性提示安装或更新，完成后重启。原内置小说入口已移除，本版本不提供新的内置小说模块或旧小说数据导入流程。

现有子应用清单中的 `minShellVersion: "0.1.0-beta.1"` 是最低兼容版本，不随本次版本号机械替换。安装器同时检查宿主 API 版本；SDK 协议见 [子应用 SDK](../MIRA_APP_PLATFORM_SDK.md)。

## 构建与验收

- 源码检查：`npm run build`、`npm test`，分别记录构建与测试的实际结果；既有失败不得写成通过。
- macOS arm64：`npm run desktop:build` 生成 ad-hoc 签名测试 DMG；`npm run desktop:release` 需要 Developer ID 证书及 Apple 公证凭据。签名、公证和系统通知验收见 [macOS 签名与发布](../MACOS_RELEASE.md)。
- Windows x64：在 Windows 上执行 `npm run desktop:build:win`，单独验收安装、启动、窗口控制、子应用和原生工具。
- 实机升级：验证 Beta 1 数据保留、版本显示、模型调用、Workbench 安装与更新、浏览器及分离窗口。静态检查和生产构建不能替代这些验收。

GitHub Release 应选择 **Pre-release**，按实际提供的附件填写平台与签名情况。本次文档和版本同步不自动创建 tag、发布 Release 或上传安装包。
