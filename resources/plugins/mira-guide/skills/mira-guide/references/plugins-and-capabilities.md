# 插件与能力

## 插件市场入口

左侧栏打开 **插件市场**：

- **公共**：浏览内置及已添加市场源中的插件。
- **本地**：查看已安装插件与独立 Skill，并管理启用状态。
- 右上角 **添加**：创建插件、添加插件市场或添加本地插件。
- **市场来源设置**：管理本地绝对路径、HTTPS 清单或受支持的 GitHub 市场源。

## 安装、启用、使用和移除

1. 在“公共”中打开插件详情，检查来源、版本、包含的能力和许可，再点 **安装**。
2. 安装后确认状态为 **已启用**。停用会让后续调用不可用。
3. 新建任务，或点 **立即试用/试用** 新建任务并填入插件引用。
4. 在任务中按能力选择：`@` 引用插件或 Agent，`/` 选择插件命令，`$` 选择 Skill，MCP 面板选择服务。
5. **移除** 只删除 Mira 的安装登记，原插件目录及已下载文件保留。

安装、启用、任务目录、会话选择、连接/授权是五层不同状态。旧任务不会自动获得后来安装的能力；见任务能力快照章节。

## 插件更新

**刷新市场** 会重新读取市场目录和已安装状态，但当前界面没有单独的“一键升级”动作：

- 本地插件直接指向所选目录；目录内容变化后会按实时来源重新校验。
- 市场插件若要换到新的清单版本，先确认没有依赖旧版本的任务，再移除登记并从刷新后的市场重新安装。
- 已有任务仍保留原能力身份快照；声明、路径或内容变化可能显示“内容已变化”或“请新建会话”。新任务使用重新登记后的目录。

不要为了“更新”直接覆盖正在使用的插件目录；这可能让当前任务的 Agent、MCP 或 Hook 校验失败。

## 五类能力的区别

| 能力 | 做什么 | 如何使用 | 关键边界 |
| --- | --- | --- | --- |
| Skill | 给主 Agent 加载专项说明和参考资料 | `$` 选择 Skill，或 `@插件` 后由 Agent 按需读取 | 本身不是后台服务；只属于任务快照中的已启用插件或本地已启用 Skill |
| Command | 把消息开头的短命令展开成固定任务指令 | `/命令` 或 `/插件:命令` | 必须位于消息开头；需要的 Skill 不可用时命令也不可用 |
| Agent | 提供可委派的子智能体角色、指令和工具范围 | `@` 或 `/` 选择，主 Agent 按需委派 | 需要工作目录且委派已开启；不会因为引用就保证运行 |
| MCP | 连接外部或本地服务，将其工具暴露给 Agent | MCP 面板为当前会话选择，或显式引用声明 MCP 的插件 | 需启用、属于任务快照、当前会话选择并成功连接；远程服务还可能需要授权 |
| Hook | 在会话、消息、工具或权限事件发生时自动运行命令 | **设置 → 事件钩子（Hooks）** 审阅并授权 | 可执行本地进程或 Shell；信任只绑定当前声明内容，内容变化后失效 |

## MCP 安装后仍不可用

依次检查：

1. **插件市场 → 本地**：插件是否已安装、已启用、无同名冲突或解析错误。
2. 当前任务是否在插件安装后新建；旧任务可能没有该插件能力身份。
3. 输入区 `/` → **MCP 服务**：服务是否“此会话已选”，是否已停用或显示不可用原因。
4. 当前任务是否正在运行；运行时不能修改选择。
5. 连接状态是否为“已连接”。失败时检查命令、环境变量、工作目录、网络或 OAuth 授权。
6. 插件声明变化时，新建任务并重新选择；不要反复在旧任务中重试失效快照。

## Hook 的额外要求

插件提供 Hook 后，进入 **设置 → 事件钩子（Hooks）**，切到“插件”范围，阅读事件、命令、参数与来源路径，再点 **审阅并授权**。插件启用不等于 Hook 已获得信任。插件、命令、参数、来源或其他声明内容变化后，原信任不会沿用，必须重新审阅。
