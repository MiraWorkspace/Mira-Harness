# 设置与安全

## 模型服务

入口：右上角 **设置 → 模型服务**。

1. 选择或添加模型服务商，核对接口地址、协议和认证方式。
2. 需要认证时添加 API 密钥；本地无需认证的服务可使用“无认证”。
3. 同步或手动添加模型，启用要在任务中使用的模型。
4. 检测连接后，回到输入区选择模型。

模型请求会发送到配置的服务商接口。提示词、选中的历史、附件和工具结果可能成为请求内容；使用云端服务前应遵守该服务的隐私与数据政策。API 密钥保存在 Mira 的本地模型配置中并用于请求，不要把密钥写进对话、项目文件、插件参数或 Hook 输出。

MCP OAuth 凭据由宿主使用系统可用的安全存储加密；如果安全存储不可用，授权会失败而不是降级为明文保存。

## 权限设置

入口：**设置 → 对话设置 → 权限**。

- **新任务默认权限**：逐次确认、自动审核、完全访问。
- **允许选择“自动审核”** 和 **允许选择“完全访问”**：控制这些高权限档位是否能在任务中使用。

完全访问只是减少操作确认，不会扩大项目目录、绕过符号链接检查、自动信任 Hook、替代 MCP OAuth，或让已停用插件恢复可用。处理陌生仓库、插件和 Hook 时优先使用逐次确认。

## Hook 信任

入口：**设置 → 事件钩子（Hooks）**。

- 全局和项目 Hook 可新建、编辑、启停；插件 Hook 只能审阅其来源声明，不能在 Mira 中改写插件源。
- Hook 可以在会话开始、提交消息、工具调用前后、权限请求和回复结束时启动进程或 Shell 命令。
- **信任并启用/审阅并授权** 只信任当前作用域、来源、命令、参数和内容修订。
- 修改 Hook、脚本声明、插件来源或参数后，修订变化，原信任失效并要求重新审阅。
- 异步 Hook 不阻塞当前任务，也不能用返回结果阻止操作或改变权限决定。

审阅时检查命令、参数、Shell、工作目录、事件、匹配规则和来源路径。不要授权会上传文件、读取凭据或执行未知下载脚本的 Hook。

## 本地数据边界

- 项目文件保留在原目录；Mira 只记录项目路径和任务数据。
- “移除插件”只移除登记，保留原插件目录或已下载文件。
- 个人任务使用 Mira 管理的个人工作区。
- 项目级 Hook 配置位于项目的 `.mira/hooks.json`；搜索忽略规则位于工作区 `.miraignore`。
- 会话、配置、自动化、授权与其他应用状态保存在 Mira 用户数据目录；不要手工编辑正在使用的数据库或信任记录。
- 路径解析会拒绝越界和指向授权根外的符号链接；插件 Skill 参考文件也只能从自身 Skill 目录读取。

## 外部扩展的信任边界

- **插件**：安装前核对市场来源、版本、文件和许可。启用后只表示组件可被发现，不自动授予工具执行权限。
- **MCP**：服务可以向 Agent 暴露工具；选择前确认服务地址、启动命令和授权范围。远程 MCP 可能把工具输入发送到第三方。
- **Hook**：会在事件发生时自动运行本地命令，风险高于只提供说明的 Skill。
- **Command/Agent**：它们能影响提示词和工具使用范围，但实际工具调用仍需通过当前权限与宿主校验。

## 安全排查

- 权限选项灰色：先在“对话设置”允许该档位。
- Hook 反复要求信任：内容或来源修订发生变化；重新核对后授权，不要直接绕过。
- MCP 等待授权：在 MCP 管理页完成 OAuth；授权回调、网络或安全存储失败时重试并检查系统环境。
- 插件能力突然不可用：检查插件是否停用/移除、目录是否移动、是否同名冲突、声明是否变化；必要时新建任务。
- 模型请求失败：检查接口地址、密钥、协议、模型启用状态和模型输入能力；公开错误会隐藏密钥，不应粘贴完整密钥排错。
